# 高専入試 ローカルVLMベンチマーク（2026年10月版）

国立高等専門学校機構が公開している入学者選抜学力検査（以下、高専入試）の問題を、研究室の Mac Studio で動く画像対応の生成AI（ローカルVLM）に解かせ、モデルごとの得点と所要時間を比べた結果の一式です。今回の条件で計測した結果の報告で、モデルの一般的な優劣を示すものではありません。計測に用いた Mac Studio は、一般財団法人放送大学教育振興会の助成により導入しました（6章）。

- 解説記事：[数学の速報](https://skeisuke-lab.com/posts/kosen-math-local-llm-benchmark/)
- このリポジトリには、問題の画像とモデルの生の出力は含めていません。問題は国立高専機構のサイト（https://www.kosen-k.go.jp/）から入手してください。

### 用語

| 用語 | 意味 |
|---|---|
| 回 | ある年度の本試験または追試験の、1教科の試験（例：令和8年度本試験の数学） |
| 試行 | 同じ条件で5回分を解かせることを1試行とします。ローカルのモデルは3試行、gpt-6.1-sol は1試行です |
| 送信単位（要求） | AIへの1回の送信。共通の条件・文章・図を使う設問のまとまりで、1回分はいくつかの送信単位に分かれます |
| 正常終了 | 応答が最後まで返り、答えの本文があった送信単位（status = completed） |
| 打ち切り | 出力の上限（output_limit）または時間の上限（timeout）に達した送信単位 |
| 空回答 | 応答は最後まで返ったが、推論（thinking）のあとに答えの本文がなかった送信単位（empty_answer） |

正常終了以外の送信単位（打ち切り・空回答）は、その単位の全問を0点にしています。

## 2. 何をしたか

### 問題

教科ごとに、次の5回分を使いました。
- 令和8年度本試験
- 令和6年度本試験
- 令和6年度追試験
- 令和7年度追試験
- 令和8年度追試験

令和7年度本試験は、AIへの指示文と採点規則を調整するために使ったので、集計から外しています。

- **英語の令和7年度追試験：** 大問6は本文が公開されていないため出題せず、79点満点で集計しました（公式の満点は100点、大問6は21点）。`unit_plans/` では `excluded_units`、`keys/` では `excluded` として区別しています。
- **理科の令和8年度本試験：** 大問6 問1 2（3点）は、国立高専機構の通知（2026-02-08、https://www.kosen-k.go.jp/news/31373 。詳細は問題PDFの1ページ目）で不成立とされ、受験者全員に得点が与えられています。このベンチマークでは、モデル間の比較に使えないため、この3点を分子からも分母からも外し、97点満点で集計しました。

### 入力と送り方

- **入力：** 公式PDFを画像にしたもの（200dpi）と、固定の指示文（`prompts/`）だけです。文字起こし、ヒント、正解、過去の回答、解答用紙は入れていません。ネット検索などの道具も使わせていません。
- **送り方：** 共通の条件・文章・図を使う設問のまとまりを1つの送信単位とし、毎回新しい会話で送りました。独立した小問は分けています（数学の大問1など）。
  - 英語の大問1〜3は、大問の冒頭の指示文をすべての設問で使うため、大問ごとに送りました。
  - 国語も、どの問も大問の本文を使うので、大問ごとに送っています。
  - どの範囲をどの単位で送ったかは `unit_plans/` にあります（説明は英語で書いています）。
- **上限：** 出力は65,536トークン（推論のトークンを含む）、1つの送信単位につき30分までです。上限に達した送信単位は、その単位の全問を0点にしました。

### 採点

- 公表されている正解と配点に照らして採点しました。正解は公式の正解PDFから転記し（`keys/`、取得元のURLとSHA-256つき）、25回分すべてを人の目で照合しています。
- **得点（主指標）：** 答えの書き方の違い（全角と半角、解答欄の記号の書き方、小問の番号の書き方など）は、決めた規則でそろえてから正誤を判定しました（`scoring/`、規則の説明は `scoring/SCORING.md`）。
- **厳格得点（副指標、数学のみ）：** 指定した書式（`ア = 9` の行）で書かれた欄だけを読んで採点した得点です。送信単位ごとの値を `results/per_question/` の `strict_points` 列に載せています（平均の表は作っていません）。
- **掲載している結果：** 本番の結果（`results/`）は、すべて数学 v1.4・数学以外 g1.9 で採点した値です。参考試行（`ablation_japanese_v2/`）も g1.9 で採点し直しています。

**採点規則を本番の後に足したこと**

数学以外の教科では、採点規則を凍結したあとに、規則を4回足しました（g1.4〜g1.7）。

- **いつ足したか：**
  - g1.4・g1.5：本番の回答を見たあと
  - g1.6：本番の回答と、国語の公式の正解を見たあと
  - g1.7：本番の回答と、理科の公式の正解を見たあと
- **何を足したか：** 英語のA・B部分や大問番号付きの書き方、ローマ数字や丸数字の読み取りです。g1.7 では、理科の入れ子の小問・名前の付いた欄の読み取り、公式の配点に合わせた部分点、2つの緩い読み取り（名前の付いた欄を順に対応させる、問番号を省いた小問を読む）を加えました。
- **点数への影響：** g1.4〜g1.7 はどれも読み取れる答えを増やす変更なので、該当する教科の点数を変えています（g1.4・g1.5 は欄の名前の読み方だけ、g1.6・g1.7 は値の読み方と部分点も含みます）。
  - 凍結した版（g1.3）のプログラムはハッシュ値しか残していないため、規則ごとの影響を、モデル×教科の点数差として示すことはできません。
- **確かめたこと：** どの規則も全モデルに同じように当てました。規則を足すたびに、それまでに採点を終えていた教科の集計が前の版と一字一句同じであることを確かめています。比べた教科は次のとおりです。
  - g1.4・g1.5：調整用の年度の4教科
  - g1.6：英語・社会と調整用の年度
  - g1.7：英語・社会・国語と調整用の年度
- **数学：** 本番の5回分を解かせたあとに変えたのは、下記の不具合修正（v1.3・v1.4）だけです。

詳しい経緯は `scoring/SCORING.md` にあります。事前に登録した採点規則ではない点に注意してください。

**公開前のレビューで直した不具合（v1.3・g1.8、v1.4・g1.9）**

公開前に、AIツールによるコードレビュー（Codex、Fable、GPT Pro）を2回行い、採点の不具合を直しました。人による査読ではありません。
- 小数・分数・複数候補の誤読（`3.9`、`3 / 4`、`¾`、`3 または 4` を `3` と読んでいた）
- 別の読み取り経路で、曖昧な回答を採用していたこと
- g1.5 の書き方を誤読していたこと

修正のたびに、本番として保存した3,352記録（通信エラーで置き換えられた2記録を含む）を採点し直しました。点数が変わったのは v1.3・g1.8 の2件で、v1.4・g1.9 では0件でした。国語の参考試行の102記録（問ごとの81記録と、比較に使った大問ごとの21記録）も g1.9 で採点し直し、点数の変化は0件でした。
- Qwen3.8 27B・数学：`エ = 4.5` を `4` と読んでいた。−4点。数学の平均が 89.3 → 89.0 になった。
- Qwen3.5 9B・理科：途中の分数の行を誤読して曖昧扱いになっていた。+2点。理科の平均が 52.6 → 52.7 になった。

## 3. 実行環境

| モデル | 開発元 | 入手元・形式（ファイルの大きさ） | コンテキスト長 | 生成の設定 |
|---|---|---|---:|---|
| Muse Glimmer 30B | Meta | lmstudio-community/Muse-Glimmer-30B-GGUF、リビジョン c34cb73（Q4_K_M、llama.cpp エンジン、18,157,012,832 バイト） | 131,072 | temperature 1.0, top_p 0.95, top_k 64 |
| Qwen3.8 27B | Alibaba | LM Studio のモデル一覧 qwen/qwen3.8-27b（MLX 4bit、16,081,678,492 バイト） | 262,144 | temperature 1.0, top_p 0.95, top_k 20, presence_penalty 0.0 |
| Gemma 4 31B | Google | LM Studio のモデル一覧 google/gemma-4-31b（MLX 4bit、18,444,515,810 バイト） | 261,120 | temperature 1.0, top_p 0.95, top_k 64 |
| Qwen3.5 9B | Alibaba | LM Studio のモデル一覧 qwen/qwen3.5-9b（MLX 4bit、5,977,257,833 バイト） | 262,144 | temperature 1.0, top_p 0.95, top_k 20, presence_penalty 1.5 |
| gpt-6.1-sol | OpenAI | OpenAI Responses API、モデル名 `gpt-6.1-sol` | — | APIの既定値（推論の強さは既定の medium、画像の解像度 detail は指定せず）。ツールなし、store=false、出力上限65,536トークン |

- **コンテキスト長：** LM Studio が報告した、読み込み時の値です（Gemma の 261,120 も、LM Studio がそのモデルに設定した値です）。
- **生成の設定の出典：** サンプリングの値（temperature・top_p・top_k・presence_penalty）は、各モデルの公開ページの推奨値に合わせました。2026年10月2〜3日に確認しました。リンクは確認時のリビジョンに固定しています（いずれも確認日時点の最新のリビジョンです）。
  - [Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B/blob/c202236235762e1c871ad0ccb60c8ee5ba337b9a/README.md)・[Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B/blob/1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0/README.md)：thinking モードの推奨値
  - [gemma-4-31b-it](https://huggingface.co/google/gemma-4-31b-it/blob/842da3794eaa0b77d5f08bae87a17459d91ff475/generation_config.json)：generation_config.json の値。min_p とペナルティは指定がないため中立の値にした
  - [Muse-Glimmer-30B](https://huggingface.co/meta-models/Muse-Glimmer-30B/blob/a4e59da52a7bc87ae7251dd5545c0dd437c44b68/README.md)：モデルカードの推奨値
- **推論（thinking）：** 4モデルとも推論は有効でした。トークン数の記録が残っている送信単位（時間の上限や通信エラーで記録がないものを除く）では、すべてで推論のトークンを出力していたことを確かめています。推論の強さは既定のままです。たとえば Muse のモデルカードは、難しい問題には推論の強さを high か xhigh にすることを勧めています。これはシステムプロンプトで指定する方式で、今回は固定の指示文だけを送る手順のため既定のままにしました。
- **ローカルの4モデル：**
  - Mac Studio（Apple M5 Ultra、メモリ96GB）の LM Studio で動かしました。
  - LM Studio の OpenAI 互換API（`/v1/chat/completions`、ストリーミング）に、`max_tokens` = 65,536 を指定して送りました。応答の `finish_reason` が `length` のものを出力の上限（output_limit）としました。`output_tokens` 列は推論のトークンを含む出力トークン数（`completion_tokens`）で、出力の上限に達した単位では LM Studio が 65,535 と報告しています。
  - 時間の上限は送信側で測り、30分を超えたら接続を切ったうえで、モデルを読み込み直して生成を止めてから次へ進みました。
  - 1つの送信単位は、1つのユーザーメッセージ（指示文のテキスト、続いてページ順の画像）です。システムプロンプトは使っていません。
  - 乱数のシードは指定していません。
  - 送信単位は1つずつ順に送り、同時には送っていません。
  - 画像は200dpiで切り出したPNGで、こちらでは縮小していません。LM Studio とエンジンの内部での処理は確認していません。
- **gpt-6.1-sol：** 画像の解像度（detail）を指定していないため、API の側で縮小されている可能性があります。ローカルの4モデルとは入力の条件が完全には同じではありません。
- **記録していないもの：** macOS・LM Studio・MLX・llama.cpp の版、LM Studio のモデル一覧から入手した3モデルのファイルのハッシュ値は記録していません。
- **計測した期間：** 2026年10月2日〜9日（日本時間）です。gpt-6.1-sol は10月3日（日本時間）に1試行だけ解かせました。

## 4. 読み方の注意

- **ばらつき：** 同じモデル・同じ問題でも、1回分の点数が試行によって大きく動くことがあります。最大は Qwen3.8 27B の令和8年度本試験の国語で、3試行が33点・0点・88点でした。
- **上位2モデル：** Muse Glimmer と Qwen3.8 27B は、今回の各3試行では、5回分の平均得点率の最小値〜最大値が全教科で重なりました。試行数が少ないため、数点の差から安定した優劣を判断することは避けてください。
- **国語：** 大問1つを1回の送信単位で解くため、出力の上限に達したり空回答になったりすると、大問全体が0点になります。27B は、45送信単位のうち出力の上限が9、空回答が5で、試行ごとに 42.8〜65.0% と大きく動き、Muse（57.6〜62.4%）よりばらつきが大きくなりました。
  - 参考に、正常終了した送信単位だけの得点率（その合計得点÷その配点合計、3試行分）を求めました。27B は 760／1,040点＝73.1%（45単位中31単位）、Muse は 904／1,500点＝60.3%（45単位中45単位）です。
  - モデルごとに対象となる問題が違うので、同じ問題での比較ではありません。この値から「最後まで書き終えれば27Bが上」とは言えません。
  - 問ごとに送る方式（v2）を試した結果は `ablation_japanese_v2/` にあります。主指標は大問ごとの方式のままです。
- **学習データ：** 問題と正解は公開済みなので、どのモデルも学習データに含まれている可能性があります。gpt-6.1-sol の知識カットオフは2026年4月30日（[OpenAI のモデルの説明](https://developers.openai.com/api/docs/models/gpt-6.1-sol)）で、今回の5回分と調整用の令和7年度本試験は、すべてそれより前に公開されています。gpt-6.1-sol の結果は参照値として扱ってください。ローカルモデルの学習データの時期は確認できていません。
- **時間：** 各送信単位について、送ってから応答が終わるまでの経過時間（送信側で計測）を合計したものです。人の解答時間とは比べられません。

| `ja-perq-1.0` | 国語を問ごとに送る試行の指示文（`ablation_japanese_v2/`） |
| `1.4`（数学）・`g1.9`（数学以外） | 採点規則の版（`scoring_version` 列。文中では数学を v1.4 と書きます） |
| 国語の v1・v2 | 国語の送り方（v1 は大問ごと、v2 は問ごと）。採点規則の版とは別のものです |
| `key_version` | 正解キーの版（すべて1） |

### 列の意味

`results/per_question/*.csv`（1行が1つの送信単位の1回の送信）：

| 列 | 意味 |
|---|---|
| `subject`・`exam`・`model`・`trial` | 教科・回・モデル・試行番号 |
| `question` | 大問の番号 |
| `subquestion` | `all` は大問全体を1単位で送ったもの。数字は、その小問から始まる送信単位です。複数の小問をまとめた単位は、最初の小問の番号で記録しています（例：英語 令和6年度本試験の大問5の `1` は、問1と問2をまとめた単位）。どの小問を含むかは `unit_plans/` の `subquestions` で確かめてください |
| `status` | completed（正常終了）、output_limit（出力の上限）、timeout（時間の上限）、empty_answer（空回答）、communication_error（通信エラー） |
| `wall_seconds` | 送ってから応答が終わるまでの秒数（時間の上限に達したものは1800） |
| `output_tokens` | 推論を含む出力トークン数。時間の上限や通信エラーで記録がないものは空欄 |
| `math_points` | 主指標の得点（数学以外の教科も同じ列名） |
| `max_points` | その送信単位の配点 |
| `strict_points` | 厳格得点。数学だけで定義し、数学以外は空欄 |
| `superseded` | True は、通信エラーのあと同じ条件で送り直したことで置き換えられた旧記録（2件）。集計には含めない |
| `scoring_version`・`key_version` | 採点規則と正解キーの版 |

`results/summary.csv`：`trials` は5回分そろった試行の数、`mean_percent` はその平均、`per_trial_percent` は試行ごとの値（` / ` 区切り）、`minutes_per_exam` は1回分の平均時間（分）、`status_counts` は状態ごとの件数（JSON の文字列）です。`summary.json` は同じ内容を丸めずに持ち、キーは `教科|モデル`、項目名は `trials`（試行番号ごとの値）・`mean`・`minutes_per_exam`・`status` です。

### 再現できる範囲

- **集計の再現：** `python tools/aggregate.py` は、`results/per_question/` について、ファイルの有無、同じ送信単位の重複、各回の満点（100点、英語 令和7年度追試験は79点、理科 令和8年度本試験は97点）、試行ごとの送信単位のそろい方を点検し、`results/summary.csv` の全行を作り直して照合します。`summary.json`・`summary_table.md`・この README の表は点検しません。
- **採点の再現：** `python tools/example.py` のように、任意の回答の文章を同じ規則で採点できます。
- **再現できないもの：** モデルの生の出力は公開していないため、このリポジトリだけで各回答を採点し直すことはできません。
