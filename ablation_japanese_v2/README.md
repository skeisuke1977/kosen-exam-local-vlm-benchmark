# 国語：問ごとに送る方式（v2）の試行（参考）

主指標の国語（v1）は、大問1つ（本文と7問前後）を1回の要求で送っています。この方式では、出力の上限に達したり空回答になったりすると、その大問の全問が0点になります。そこで、本文の画像はすべて付けたまま、問1つずつ別の要求で送る方式（v2）を試しました。

- **指示文：** `japanese_perq_prompt_v1_0.txt`（`ja-perq-1.0`）。問番号を指定して、その問だけに答えさせます。このファイルの改行は、実際に送ったものと同じ CRLF です（SHA-256 `e1b7a2cdce5b8b0f51316bb1ed09a0247cc06690cda663252d9860416a1e5c08`）。
- **上限と生成の設定：** 出力の上限（65,536トークン）、時間の上限（30分）、生成の設定は v1 と同じです。
- **試行数：** 各1試行です。
- **採点：** CSV の得点は、本番の結果と同じ採点規則（g2.0）で採点し直した値です（`scoring_version` 列）。
- **v1 の指示文：** 比べた v1 の結果は、本番と同じ指示文 `prompts/general_prompt_v1_0.txt` で解かせたものです。令和7年度本試験の v1 は、CSV では `g1.0-dev`（調整用の年度で使ったときのラベル）と記録されていますが、指示文は `g1.0` と同じものです（SHA-256が一致）。

CSV の列は、本体の README の5章と同じ意味です。`condition` 列は「指示文の版|送り方|出力上限」、`prompt` 列は指示文の版です。

## 結果

### 令和7年度本試験（調整用の年度、100点満点）

データ：`2025_japanese_main_summary.csv`・`2025_japanese_main_trials.csv`

| モデル | v1（大問ごと） | v2（問ごと） | v2で0点になった問（理由） | 1回分の時間 v1 → v2 |
|---|---:|---:|---|---|
| Qwen3.8 27B | 77 | 68 | 1問（空回答、8点分） | 約19分 → 約75分 |
| Muse Glimmer | （未実施） | 79 | 1問（空回答、4点分） | — → 約48分 |

この年度では、27B は v1 でも打ち切り・空回答が起きていません。そのため、0点になる送信単位を減らす効果は確かめられませんでした。

### 令和8年度本試験（本番の5回分の1つ）

データ：`2026_japanese_main_summary.csv`・`2026_japanese_main_trials.csv`

| モデル | v1 試行1 / 2 / 3（平均） | v2（1試行） | v2で0点になった問（理由） | 1回分の時間 v1（平均）→ v2 |
|---|---|---|---|---|
| Qwen3.8 27B | 33 / 0 / 88（40.3） | 81点（100点満点） | 2問（出力上限） | 約49分 → 約109分 |
| Muse Glimmer | 51 / 82 / 66（66.3） | 72点（91点満点、79.1%） | なし | 約19分 → 約50分 |

Muse の v2 は、計算機の利用時間の都合で最後の1問（大問3 問6、9点）を解いておらず、91点満点での値です。

## 読み方

- **27B：** v1 では、出力の上限や空回答で大問ごと0点になることがあり、試行ごとに0〜88点と大きく動きました（試行2の0点は、3つの大問のうち2つが出力の上限、1つが空回答だったためです）。v2 で0点になったのは2問だけで、打ち切りが起きてもその問だけが0点になるため、1回の打ち切りで失う配点は小さくなります。ただし v2 は1試行なので、試行間のばらつきが減るかどうかは確認できていません。
- **Muse：** v2 は1問（9点）を解いていない91点満点の結果なので、100点満点の v1 とは直接比べられません。
- **時間：** 1回分の時間は、比較できた3つの条件で v1 の約2.2〜4.0倍でした（令和7年度本試験の27B：18.6分→74.8分で4.0倍、令和8年度本試験の27B：49.1分→108.5分で2.2倍、令和8年度本試験の Muse：19.2分→50.2分で2.6倍。Muse の v2 は1問少ない）。
- **主指標：** v1 のままです。v2 を主指標にするかは、5回分を複数試行で比べてから判断する必要があります。
